# Survey data cleaner

Turns a raw field-survey export (KoboToolbox / ODK / Excel style) into an analysis-ready dataset, plus a log of every problem found and what was done about it.

## The problem

Field survey data never arrives clean. Enumerators type answers differently, tablets submit the same form twice, and impossible values slip through:

- `F`, `Female`, `P`, `Perempuan` all meaning the same thing
- `Yes`, `Ya`, `1`, `TRUE` in the same column
- dates in four different formats, some ambiguous (is `05/03/2026` 5 March or 3 May?)
- a respondent aged 999, a household of 45 people, more under-5 children than people in the house
- ANC (antenatal care) visits recorded for respondents who aren't pregnant
- GPS points at `0, 0` or in another province

Cleaning this by hand in Excel takes days and leaves no record of what was changed.

## What the script does

1. **Standardizes** sex codes, yes/no answers, district names, facility types, phone numbers (`08…` → `+62…`) and dates. Ambiguous dates are resolved using the fieldwork period.
2. **Validates** value ranges, household logic, skip logic, fieldwork dates, GPS inside the survey area and required answers.
3. **De-duplicates** forms that were submitted twice.
4. **Reports** everything in one Excel file:
   - **Summary**: before/after counts, issues by type, and issues per 100 forms by enumerator (shows who needs retraining)
   - **Clean Data**: the analysis-ready dataset, with an `issue_count` per form
   - **Issues Log**: every problem, with the original value and the action taken

Invalid values are **blanked, never guessed**, and every change is logged, so nothing disappears silently.

## Run it

```bash
pip install -r requirements.txt

# 1. make the sample survey export (fake data)
python make_sample_survey.py

# 2. clean it
python clean_survey.py sample_survey_export.csv

# optional: set your own fieldwork period and output name
python clean_survey.py sample_survey_export.csv --start 2026-03-01 --end 2026-04-30 --out cleaned.xlsx
```

Sample output:

```
Done: 825 raw submissions -> 800 clean, 514 issues logged -> survey_cleaned.xlsx
```

In the sample run, 25 duplicates were removed, and one enumerator turned out to have nearly 5× the error rate of the others.

## Adapting it to another survey

All survey-specific rules sit at the top of `clean_survey.py`: district list, valid ranges, survey-area bounding box, required fields, and the code mappings. Change those and the rest works as is.

## About the data

Everything here is **made-up sample data** generated by `make_sample_survey.py`, modelled on a household health survey in Kabupaten Pringsewu, Lampung. No real respondent data is included.
